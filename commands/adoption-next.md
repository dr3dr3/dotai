Pick up the next unblocked issue from the "AI Operating Model Adoption" Linear project and start working on it with full context loaded.

Usage: `/adoption-next` (auto-picks highest-priority unblocked issue) or `/adoption-next AGE-25` (work a specific issue)

This is the session-kickoff command for executing the AI operating model adoption programme (Linear project: AI Operating Model Adoption, team: Agentic Development, prefix AGE). It replaces manual context-carrying between Claude Desktop strategy sessions and Claude Code build sessions.

## Prerequisites

Same as `/linear-work-on-task`: `LINEAR_API_KEY` set, `gh` authenticated, target repos cloned. Additionally, `ai-context` must be cloned and current (`git -C <ai-context> pull --ff-only`).

## Canonical context (read before working — always current in ai-context on main)

- `explanation/strategy/ai-operating-model.md` — patterns, boundaries, governance (the constitution)
- `explanation/strategy/ai-flexibility-seams.md` — seam contracts + portability rules (binding on implementation choices)
- `explanation/decisions/2026-07-10-1..3` — gh-aw platform, gateway (ADR-A), harness strategy (ADR-B, as amended: Claude engine only; AGENTS.md centrally generated by ai-devex)
- `plans/active/2026-07-10-repo-consolidation-work-plan.md` — W1–W8 per-repo work detail
- `plans/active/2026-07-10-ai-adoption-roadmap.md` — streams + sequencing
- `plans/active/2026-07-10-doc-stocktake-remediation.md` — R1–R6 doc sessions

## Workflow

### Step 1: Select the issue

If an identifier was given, use it. Otherwise query Linear (GraphQL, per `/linear-work-on-task` conventions) for issues in project "AI Operating Model Adoption" where state is Backlog or Todo, **no incomplete blocking issues**, ordered by priority then stream prefix (A before G before D before B before R). Present the top pick + two runners-up; confirm with the user before proceeding.

### Step 2: Load context

1. Read the issue description — it names the relevant work-plan sections (W#), doc sessions (R#), and ADRs.
2. Read ONLY the referenced sections of the canonical docs above (do not load all docs wholesale).
3. Check the issue's blocking/blocked-by relations and note any gates or kill criteria named in the description — these are binding.

### Step 3: Work the issue

- Move the issue to In Progress (Linear API).
- Follow the referenced plan sections exactly; where the plan and reality diverge, STOP and surface the divergence to the user rather than improvising — plans get amended in ai-context, not silently bypassed.
- Respect the standing rules: seams doc portability rules (no direct provider SDK imports outside the model client; skills to agentskills.io core spec; MCP-only integrations), safe-rollout ladder for any agentic workflow, CODEOWNERS on all workflow files.

### Step 4: Ship

- Use `/linear-ship-task` conventions: conventional commits, draft PR(s), Linear → PR Review with PR links as a comment.
- If the work changed anything the canonical docs assert (a decision, a sequence, a scope), include the ai-context doc update in the same session — the docs-stay-true rule is what makes this command work.
- Add a closing comment on the Linear issue: what was done, what was learned, anything the next session should know.

### Step 5: Suggest the next session

After shipping, re-run the Step 1 query and tell the user what's now unblocked, so the next session starts with zero warm-up.
